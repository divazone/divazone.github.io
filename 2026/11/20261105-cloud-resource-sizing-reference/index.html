前言

對於多數系統，硬體資源配置可以先以一組公版規格為基準，再透過監控進行效能調整或組件置換。本篇提供大家一個簡單的選擇方向，各大 CSP (Cloud Service Provider) 分別都有提供對應的 VM 實例資源配置參考，可先用使用情境進行初始評估，再選擇合適的 vCPU、記憶體、磁碟與網路規格。

以下整理 2026 年可參考的代表系列，並非完整機型清單；實際供應仍需確認部署區域、配額與容量。各家的官方資源配置參考如下：

  • Google GCP
  • Amazon AWS
  • Microsoft Azure

選規格時也要確認 x86 / Arm 架構、作業系統映像與軟體相容性，相同的 vCPU 數不代表相同的實體核心數或效能。除了 CPU 與記憶體，磁碟 IOPS、吞吐量及網路頻寬也可能是瓶頸。

後續可以依監控結果調整規格，但 resize 通常涉及停機或重新啟動，跨架構或不相容系列可能需要重新部署，也要確認本機暫存磁碟資料的保存方式。實際操作可參考 AWS、GCP 與 Azure 的調整方式。

各大廠配置清單

Amazon AWS

AWS 針對不同使用情境提供多種 Amazon EC2 Instance Types，可以先從下列分類選擇：

  1. 一般用途 (General Purpose) T3 / T4g / M8i / M8a / M8g
    • T3 / T4g: 適合平均 CPU 使用率較低、偶爾需要突發效能的網站、開發與測試環境，需留意 CPU credits 與 Unlimited 模式的額外費用
    • M8i / M8a / M8g: 適合 Web 應用程式、中小型資料庫、資料處理任務、快取及企業應用程式的後端伺服器
  2. 運算優化 (Compute Optimized) C8i / C8a / C8g
    • 適合高效能 Web 伺服器、科學建模、批次處理、分散式分析、遊戲伺服器及影片編碼等 CPU 密集型工作負載
  3. 記憶體優化 (Memory Optimized) R8i / R8a / R8g / U7i
    • R8i / R8a / R8g: 適合高效能資料庫、分散式記憶體快取、即時大數據分析及其他記憶體密集型應用程式
    • U7i: 適合 SAP HANA 等需要超大記憶體容量的資料庫與企業應用程式
  4. 加速運算 (Accelerated Computing) P5 / P6-B200 / G6 / G7 / F2 / Inf2 / Trn2
    • P5 / P6-B200: GPU 加速的機器學習訓練、推論及高效能運算
    • G6 / G7: 3D 視覺化、圖形密集型遠端工作站、影片編碼及機器學習推論
    • F2: 使用 FPGA 進行基因體研究、財務分析、即時影片處理及搜尋等自訂硬體加速
    • Inf2 / Trn2: 分別使用 AWS Inferentia 與 Trainium 加速器進行推論與訓練，需確認框架與 AWS Neuron 的支援情況
  5. 儲存優化 (Storage Optimized) I7i / I8g / D3 / D3en
    • I7i / I8g: 提供本機 NVMe SSD，適合高 I/O 的 NoSQL 資料庫、搜尋引擎、交易處理及分析工作負載
    • D3 / D3en: 提供高密度 HDD 儲存，適合資料倉儲、Hadoop、分散式檔案系統及大量循序讀寫的資料處理
  6. 高效能運算 (High Performance Computing) Hpc7a / Hpc8a
    • 適合計算流體動力學、有限元素分析、氣象模擬等需要多節點協同運算的工作負載

上述 M / C / R 系列中的 i、a、g 分別代表 Intel、AMD 與 AWS Graviton 處理器，其中 Graviton 採用 Arm 架構。

Vantage Instances 是原 EC2Instances.info 的第三方規格與價格比較工具，可以直接搜尋需要的資料，選型時再對照 AWS 官方規格與區域供應情況。

Google GCP

Google Cloud 的 Compute Engine 機型總覽 也依照使用情境區分機型家族，可以先從下列分類選擇：

  1. 一般用途 (General-purpose) E2 / N4 / N4D / C4 / C4A / C4D: 適合 Web 應用程式、微服務、資料庫及開發測試環境，可依成本與效能需求選擇系列
  2. 運算優化 (Compute-optimized) H3 / H4D: 適合科學模擬、工程分析及其他 HPC 工作負載
  3. 記憶體優化 (Memory-optimized) M3 / M4: 適合 SAP HANA、記憶體內資料庫及需要大量記憶體的分析工作負載
  4. 儲存優化 (Storage-optimized) Z3 / Z4D: 適合需要高本機儲存吞吐量與 IOPS 的資料庫、搜尋及分析工作負載
  5. 網路優化 (Network-optimized) C4N / M4N: 適合需要高網路頻寬、封包處理效能或區塊儲存 I/O 的工作負載
  6. 加速器優化 (Accelerator-optimized) A3 / A4 / G2 / G4: 適合 GPU 加速的訓練、推論、圖形與高效能運算

同一系列也可能提供 standard、highmem、highcpu 等不同的 vCPU 與記憶體配比；部分系列支援自訂機型，可在允許範圍內調整配置。

GPU 規格與支援組合 可以用來比較 GPU 型號、單卡記憶體、數量與互連方式。實際需求還是要依模型大小、精度、訓練或推論方式及實測結果判斷，不能只看 GPU 數量。

如果要拿雲端規格參考自建 Kubernetes，三家都可作為起點，但仍需考慮 Pod requests、系統預留資源及 DaemonSet 的用量，VM 的總容量不等於可分配給應用程式的容量。

Microsoft Azure

Azure 的 虛擬機器大小總覽 同時適用於 Linux 與 Windows，可以先依工作負載選擇系列，再確認作業系統映像、軟體與授權需求：

  1. 一般用途 (General Purpose) B / D: B 系列適合低平均 CPU 使用率、偶爾需要突發效能的工作負載；D 系列適合 Web 服務、企業應用程式及一般資料庫
  2. 運算優化 (Compute Optimized) F: 適合 CPU 密集型應用程式、批次處理及網路設備
  3. 記憶體優化 (Memory Optimized) E / M: 適合大型資料庫、快取及記憶體內分析，其中 M 系列提供更大的記憶體容量
  4. 儲存優化 (Storage Optimized) L: 適合需要高磁碟吞吐量與 IOPS 的資料庫及資料分析工作負載
  5. GPU 加速 (GPU Accelerated) NC / ND / NV: NC / ND 系列可用於 GPU 運算與 AI 工作負載；NV 系列主要用於虛擬桌面與圖形工作負載
  6. FPGA 加速 (FPGA Accelerated) NP: 適合自訂硬體加速、影片轉碼及搜尋分析
  7. 高效能運算 (High Performance Compute) HB / HX: 適合科學模擬、工程分析及電子設計自動化等工作負載

Microsoft 提供的規格資料也涵蓋 RDMA 相關應用，有多節點低延遲通訊需求時，可進一步查看 HPC 與 GPU 系列的網路規格，並確認所選機型的 RDMA 支援與部署限制。
